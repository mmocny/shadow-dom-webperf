Part 1 · The Problem

What Breaks Today When a Site Uses Shadow DOM?

Moving UI into Web Components currently breaks Web Performance APIs in three different ways:

LCP (& CLS)

Missing or null Attribution

Safari ignores Shadow DOM in LCP entirely (310655@main). Chrome & Firefox measure it, but strip entry.element to null while leaking url (LCP #152).

Note: CLS has the same issue (sources[i].node → null)
Event Timing & LoAF

Inconsistent Edge Cases

Composed events retarget target to the host, but shadow-confined events and no-listener events (crbug/1367329) become target: null in Chrome (while Safari still retargets no-listener events to the host), and targetSelector (#126) / LoAF invoker leak inner shadow IDs.

Host retargeted · null on confined/no-listener · leaked IDs
Element & Container Timing

Completely Unsupported

elementtiming (#3) and containertiming (#14) inside Shadow DOM are completely dropped—even for the component's own author.

Zero entries emitted inside ShadowRoots

DOM Events Bubble Out—and Retarget to the Shadow Host

When a user clicks inside an open or closed Shadow Root, the outer page receives the event—with event.target rewritten via WHATWG DOM retarget():

1

Composed Clicks Exit

UI events (click, pointerdown, keydown) have composed: true and bubble out to window across both open and closed shadow roots.

window.addEventListener('click') fires
2

event.target Retargets

An inner click on <button#secret-btn> is automatically rewritten at the shadow boundary to the outermost light-DOM Shadow Host.

event.target → <closed-demo-button>
3

Internal Hover Stops

When sliding between two pills inside the same shadow root, retarget(target) == retarget(relatedTarget), so mouseover stops at the ShadowRoot.

Internal A ↔ B hover stays private

Hit-Testing & Layout Treat the Shadow Host as a Public Box

Even inside a closed Shadow Root, rendered coordinates participate in document hit-testing—and retarget to the Shadow Host:

1

Host Box Is Observable

When content inside a closed shadow root expands the component, light-DOM getBoundingClientRect() and ResizeObserver measure the exact pixel delta.

host.getBoundingClientRect()
2

elementFromPoint(x, y) Retargets

Even inside a fixed-size closed shadow root, hit-testing any screen coordinate (x, y) returns the Shadow Host—treating the inner tree as a black box.

elementFromPoint(x, y) → <my-closed-hero>
3

Black Box = Encapsulation

Attributing a screen region or layout shift to the Shadow Host tells the page owner which component was involved without revealing which inner child caused it.

Component attribution ≠ inner DOM leak

Part 2 · Pure Web Platform Proof (Zero Performance APIs) · 3 of 3

Slow Subresources Inside Shadow DOM Delay window.onload

Even when an <img> is encapsulated inside an open or closed Shadow Root, its network loading participates in the outer document's lifecycle:

1

DOMContentLoaded Fires Early

The outer HTML parser finishes immediately (`~15ms`), while slow-loading <img> elements inside the open and closed Shadow Roots continue fetching.

document.readyState === "interactive"
2

Delays Outer window.onload

Per WHATWG HTML, both open (`1.2s`) and closed (`2.4s`) shadow images delay the outer document's window.onload until the slowest one completes.

window.onload waits for closed shadow <img>
3

Timing ≠ Inner DOM Leak

The outer page observes when the component's subresources finish loading, without gaining a reference to the inner <img> node itself.

Shared page lifecycle · Encapsulated node

Part 3 · Shadow DOM Model

The "Tree of Trees" vs. The "Flattened Tree"

DOM APIs see separate trees divided by the Shadow Boundary, while layout, paint, and input operate on the unified Flattened Tree (MDN · CSS Scoping §3.1).

Part 3 · Shadow DOM Model

What Shadow DOM Encapsulates—And Why

Per MDN, Shadow DOM exists so "code running in the page cannot accidentally break a custom element by modifying its internal implementation."

1. Encapsulated DOM Tree

No Live Inner Node Leaks

querySelector and CSS don't cross into a ShadowRoot. Likewise, global APIs must not return live inner Element references (which let page code mutate internals or call el.getRootNode() on a closed root).

Protect internal DOM from page mutation
2. Shared Flat Tree (CSS §3.1)

Rendering Is Never Hidden

Layout, geometry, paint, and hit-testing all operate on the single document-wide flat tree. Measuring when or how much pixels painted cannot break a component's implementation.

Layout, paint & input are page-wide
3. The Safe Boundary

Retarget to the Shadow Host

When the platform reports a flat-tree event or paint to the page, it retargets attribution to <my-component>—a light-DOM element the page already owns.

innerNode → retarget() → <my-component>
Part 3 · Shadow DOM Model

open and closed Behave Identically by Default

Across WHATWG DOM and HTML, mode is only checked in 4 legacy APIs from 2015. All modern APIs treat open and closed the same.

1

Author open & closed

Both encapsulate their inner DOM tree by default. The only difference is whether host.shadowRoot hands out a capability reference.

Default rule: open == closed
2

The Only 4 Exceptions (2015)

1. host.shadowRoot
2. node.assignedSlot
3. slot.assignedNodes({flatten:true})
4. event.composedPath()

No newer spec checks mode == "open"
3

User-Agent (UA) Shadow Roots

Internal browser implementation of native controls (<video controls>, <input type="range">). Not author DOM.

Exclude UA internals from WebPerf
Part 4 · Expanding to Web Performance APIs

Two Audiences for Web Components (element-timing#3)

Distinguishing Component Users from Component Authors explains both what is shown by default and what requires opt-in:

1

Component Users (Default)

Page owners want timings for the component in its entirety (retargeted to <my-host>), plus sub-elements they pass via <slot> (which retarget() preserves automatically!).

Default: Host + Slotted Light DOM
2

Component Authors (Opt-In)

Widget authors hold the ShadowRoot reference and want inner node attribution plus entries filtered from the main timeline (e.g., internal elementtiming / containertiming & confined events).

Opt-in: Inner nodes + filtered entries
3

Browser Internals (UA)

Neither audience owns internal browser implementation of native controls (<video controls>). Treat open == closed, and exclude UA shadow trees.

open == closed · Exclude UA trees

Part 4 · Web Performance Demos · Reproducing w3c/largest-contentful-paint#152

Three LCP Bugs in a Single Closed Shadow Root (lcp#152)

When progressive content paints inside a single closed custom element (<lcp-shadow-probe>), three different things go wrong today:

1. Inline <span> (0ms)

Leaks Past Inline Host

Because custom elements default to display: inline, Paint Timing text aggregation walks past the shadow boundary to the outer light-DOM <div#light-wrapper>!

element → <div#light-wrapper> (Wrong!)
2. Block <p> (450ms)

Drops Host Attribution

When a block <p> paints inside the closed shadow root, it is the new containing block—so exposed for paint timing returns element: null and id: "".

element → null (Host lost!)
3. Inner <img> (950ms)

Leaks Private Image URL

When an <img> paints inside the closed shadow root, entry.element is null—but entry.url exposes the full private shadow image URL!

entry.url → "https://..." (Leaked!)

Part 5 · Core Proposal · Audience 1: Component Users (Default)

Default View: retarget for performance timing

Shared Algorithm: retarget for performance timing(node, document, allowedScopes = « »)
  1. If node is null, disconnected, or its shadow-including root is not document, return null.
  2. If node is a pseudo-element, set node to its ultimate originating element.
  3. If node's root is a user-agent shadow root, return null (unless eligible via an explicit host rule like <input value>).
  4. While node's root is a ShadowRoot root not in allowedScopes: set node to root's host.
  5. Return node.
1

Host + <slot> Automatic!

Inner shadow nodes retarget to <my-host> (with LCP.url = ""), while slotted light-DOM children (getRootNode() === document) return directly!

2

Cap Inline Text at Host

Stop Paint Timing text aggregation at Shadow Host boundaries so inline custom elements never leak to <body>.

3

Deduplicate on Inner Node

Keep LCP's "already reported" set keyed on the inner node so progressive paints in one host still emit.

Part 5 · Stretch Goal · Audience 2: Component Authors (Opt-In)

Component Author View: Capability Opt-In on observe()

When a Component Author holds a ShadowRoot reference, passing it to observe() unlocks both inner attribution and entries filtered from the main timeline: 

dictionary PerformanceObserverInit {
  DOMString type;
  boolean buffered;

  // 1. Unlocks inner attribution + shadow entries
  //    for listed ShadowRoots (open or closed):
  sequence<ShadowRoot> shadowRoots = [];

  // 2. Scopes Container / Element Timing to a
  //    subtree + authorizes its TreeScope:
  Node root;
};

Two Things Unlocked for Component Authors

  • 1. Filtered Entries Delivered: Emits entries that are completely filtered from the main Document timeline—internal elementtiming, internal containertiming, and shadow-confined events.
  • 2. Un-Retargeted Inner Attribution: Stops retarget() at this.#sr, exposing the inner element / node, inner id, and full inner LCP.url.
  • Global Buffer Isolation: performance.getEntriesByType() stays strictly filtered & retargeted to Document.
Part 5 · Call to Action for WebPerf WG

4 Decisions for the Working Group

1

Include Author Shadow DOM; Exclude UA

Update Paint Timing & LCP to traverse shadow-including descendants for open and closed roots, while excluding User-Agent shadow trees.

Unblocks Safari/WebKit interop (#152)
2

Component User Default: Retarget to Host

Retarget LCP.element, CLS.sources[i].node, LoAF.invoker, and ContainerTiming to the Shadow Host (preserving <slot> children and clearing inner LCP.url).

Component in its entirety + slots
3

Cap Inline Text & Decide targetSelector (#126)

Stop Paint Timing text aggregation at Shadow Host boundaries. Decide if EventTiming.targetSelector pierces open roots like composedPath() or stops at the host.

Open vs. Host selector decision
4

Component Author Opt-In: { shadowRoots, root }

Incubate shadowRoots & root on PerformanceObserverInit to unlock inner node attribution AND shadow-filtered entries (element, container, confined events).

Unlocks inner nodes + filtered entries
